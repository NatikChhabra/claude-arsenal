# Slides, Prototypes and Deliverable Formats

Use when the output is a slide deck, a clickable prototype or mockup, a set of variations to choose between, a developer handoff, an HTML email, a social/OG image, or anything that leaves as print or PDF.

## Pick the format first
- HTML is the tool, not the medium. A deck is a run of posters, a prototype is an app, an email is a 2003-era table document, a flyer is a sheet of paper. Never build a web page when the brief is one of these.
- Mode per format: pitch/keynote deck = Persuade boldness; deck sent to be read alone = Read (calmer, more self-contained text, same type floors); prototype = the mode of the surface it simulates; email = Persuade or Read in a tiny palette; print = Read unless it is a poster or flyer.
- Ask only what changes the build (format, length in minutes or slide count, audience, export target, fidelity). "Deck for the eng all-hands, 10 min, from this PRD" needs no questions. Question rules: process.md.

## Slide decks

### Canvas and stage
- Author at 1920×1080 (16:9). Scale the whole deck into a letterboxed full-viewport stage with `transform: scale()`; never reflow slides.
- Prev/next controls sit OUTSIDE the scaled element. Support ←/→, Space, PageUp/PageDown, Home/End, tap zones, a slide counter, and keep position in the URL hash or localStorage.
- Each slide is a static `<section>` in the HTML (directly editable), never generated by JS. Label it `data-screen-label="01 Title"`, 1-indexed.
- Give each slide's single inner wrapper `height:100%`, or full-bleed art collapses and leaves a blank strip.
- Copy a proven stage verbatim rather than hand-rolling one; fill its `<section>` slots.
- Set `background` explicitly on every section.
- Keep decks under ~50 slides. Reference images by path, reuse one file instead of several crops.

```js
const s = Math.min(innerWidth / 1920, innerHeight / 1080);
deck.style.transform = `translate(-50%,-50%) scale(${s})`; // deck: position:absolute; left:50%; top:50%; width:1920px; height:1080px
```
```css
@media print { @page { size: 1920px 1080px; margin: 0 } #deck { transform: none; position: static }
  section { display: block !important; break-after: page } .controls { display: none } }
```
- Print must drop the stage transform and show every slide, not only the active one, with reveal animations at their end state (recipe under Print).

### Type scale (define in `:root` before any slide; use only these)
```css
:root{
  --pad:128px; --pad-foot:160px;        /* edges; bottom padding when a footer band exists */
  --type-display:96px;                   /* title and statement lines, lh 1.05-1.1 */
  --type-title:64px;                     /* content slide headings, lh 1.1-1.15 */
  --type-point:44px;                     /* agenda and key points (40-48) */
  --type-body:32px;                      /* sentences (28-32), lh 1.3-1.4 */
  --type-small:24px;                     /* labels, captions, cells, source line: the floor */
  --type-figure:180px;                   /* big numbers (160-200), lh 1 */
  --gap-title:52px; --gap-item:28px;
}
```
- Use 4-5 of these sizes per deck, never more. Steps must be obvious from the back of the room.
- Floor 24px for everything, including table cells, axis labels and footers. Titles ≥48px. If text only fits at 20px, there is too much text: cut or split.
- Points from the user: px = pt × 1.333 (36pt = 48px). State the conversion once.
- Smaller canvas: at 1280×720 multiply every value by 0.667.
- Display tracking -0.02 to -0.03em; body 0; `text-wrap: balance` on titles, `pretty` on sentences. Details: typography.md.
- Google Slides or PPTX export: Google Fonts only, ≤2 families, load only the weights used, no brand or local fonts (closest Google match, flagged).

### Margins, width and height budgets
- Edges 128px (100px only for dense reading decks). Flow area inside 128px margins: 1664×824px.
- Measure: 1664px is too wide for sentences. Body in an 800-1000px column (`width:960px`, or `flex:1` beside a figure); display lines ~1400px.
- Longest word sets the minimum box width: ~0.6 × font-size per character, more for bold or caps, plus padding. At 44px, 5 cards across 1664px hold ~11 characters each. Count before choosing columns.
- Height budget, worked: 2-line 96px heading at lh 1.1 ≈ 210px; gap 48px; each table row ≈ 2.1 × font-size per text line (32px → ~70px, a 2-line cell counts twice); 9 rows ≈ 630px, which does not fit under that heading. Fix with 24-28px tables or split the slide.
- Card height = lines × font-size × line-height + padding. Never set a fixed `height` smaller than the content; leave height out.
- Footer band (page number, source, logo): ONE pinned 24px row at `bottom:64px`, identical position on every slide that has one. Those slides get `padding:128px 128px 160px`, so flow stops at y 920 (792px budget).
- Pin (`position:absolute`) only what flow cannot do: footer band, a corner badge, a full-bleed backdrop listed first in the HTML, labels over an image. Everything else flows.

### Composition
- Content slides: heading at the same y on every slide; spread the body over the full height with `justify-content:space-between` or a `flex:1` spacer. Never centre a column that has a heading above it (the heading hops 20-60px between slides).
- Centre only slides with no heading: statement, quote, closing line.
- Open space under a title or statement slide is correct. A content column that stops at 60% of the height reads as unfinished.
- Parallelism: section headers look identical; repeated elements sit in the same place; slides of one kind share markup (padding, gap, sizes).
- A matrix is ONE grid (`display:grid; grid-template-columns:repeat(3,1fr)`), filled row-major, so rows align across columns. Never three independent column stacks.
- Card row: `display:flex; gap:32px` with `flex:1` children; cards share a top and bottom edge.
- Max 3 levels of nesting per slide; deeper means split the slide.

### Slide types (decide the system out loud before building)
| Type | Recipe |
|---|---|
| Title / closing | Dark ground, display line ≤2 lines, one subline at 32px, generous open space. Close on the ask or the one thing to remember, never "Thank you / Questions?" alone |
| Section divider | Identical layout every time; section name at display size; alternate dark/light grounds |
| Statement | One sentence ≤~25 words at 64-96px, centred or on the left third, nothing else |
| Big number | Figure 160-200px lh 1 + caption 28-32px in the soft tone; the caption names the baseline ("41% faster ramp than Q2") |
| Content | Heading + one structure: table, diagram, card row, image + 3 points |
| Quote | Quote ≤3 lines at 44-64px, real attribution at 24-28px. Never invented |
| Full-bleed image | Photo aspect-filled to all 4 edges; text in a calm corner ≥64px in, on the deck's one scrim if needed |
| Screenshot / diagram | Aspect-fit, never cropped or overlaid; labels as real text pinned over the image box |
| Comparison | One grid or one table, both sides sharing rows |

### Writing
- Outline first: write the whole title sequence in ONE grammatical style, either topic noun phrases ("Market research") or action titles ("Asia is our largest market"). Reading only the titles must tell the story. Share the title list in chat before building; wait only if the brief was unclear.
- A title introduces its slide. No verdict titles, no fake tension ("It's not X. It's Y."), no "The magic moment", no punchlines. Copy rules: copy.md.
- One idea per slide. More short slides beat one crowded slide.
- Per point, choose the best form: table, diagram, quote, image, card row, big number. Bullets are the last resort; ≤5 bullets of ≤1 line each.
- A section/chrome label carries wayfinding (section name, source) and never restates the title; at most one per slide, sentence case or caps at 24px.
- Speaker notes only when asked. Then the notes hold a conversational full script and the slides go visual-first (figures, quotes, images, one-line headlines). One `<aside>` per section, last child.
- Never add filler slides, stats or icons to fill space; ask before adding material the user did not give.

### Rhythm and grounds
- 1-2 ground colours: dark for open/close and dividers, light for content, accent ground for the ONE number or sentence to remember.
- Never 3+ consecutive slides on the same ground. A deck of 8+ needs ≥1 dark hero, ≥1 light hero and ≥1 dark body slide. Write a rhythm table (slide → type → ground) before coding; check with `grep 'class="slide'`.
- Never 2+ hero slides (title, divider, statement) back to back, nor 4+ content slides without one. Alternate airy slides (big number, question, quote) with dense ones (table, image grid, process).
- Never the same layout 3 times in a row; mix full-bleed images, big numbers, quotes, tables, text.
- One spelling per term across the deck; page number as "5 / 27" in the footer band only, never repeated in a corner.
- Data slides, screenshots and processes sit on light grounds.

### Data slides
- One message per chart, stated in the title. Pick the chart by question (time → line, ranking → sorted bars, part-to-whole ≤5 parts → 100% bar or thin ring). Chart catalogue: apps.md.
- Back-of-room limits: ≤7 categories, ≤4 lines, ≤1 highlighted series in the accent with the rest in grey.
- Direct labels on the marks; no legend for one series. Value labels, axis labels and category labels ≥24px.
- Bars stand on ONE baseline: a fixed-height track with `align-items:flex-end`, value above each bar, label below the track. Small multiples share track height and scale.
- 3-5 faint gridlines, no y-axis line, no 3D, no rotated labels, no gradient fills.
- Tables: 24-32px, header row, numbers right-aligned with `tabular-nums`, fixed decimals. Under a 2-line display heading that is ≤8 rows at 32px or ≤11 at 24px; past that, split rather than shrink.
- Every figure has a source line in the footer band at 24px ("Source: People Ops survey, Q3, n=212"). Never invent a number; use a labelled stub.
- Few numbers → big-number slide, not a chart.

### Images, icons and diagrams
- In image grids, crop only at the bottom (`object-fit:cover; object-position:top`) inside a fixed-height frame; use standard ratios (16:10, 4:3, 3:2, 1:1, 16:9), never the source's odd ratio.
- No shadows or heavy borders on images; at most a 1-4px radius.
- Diagram labels are real text over the image, never `<text>` inside the SVG (fonts fail and exports drop them).
- No emoji. Icons from the design system or one pinned library (e.g. `lucide@0.469.0`), never `@latest`, never an icon on every bullet. Icon boxes ≥32px (48px beside 24px text); a pale or accent icon sits on a solid chip.
- Text over a photo always gets the same protection deck-wide: one scrim value (e.g. `rgba(20,20,19,.6)`) or one solid card, never mixed.

### Animation
- Most slides need none. Animate only when the order of reveal carries meaning: 1-2 slides in 10.
- The authored CSS is the final visible state; one effect per element; no infinite decorative loops; respect reduced motion. Timing: motion.md.

### Deck tells (full list: tells.md)
- A short block hanging under the title with the lower half empty; every slide centred; heading hopping.
- Agenda slide in a deck under ~10 slides; closing on "Questions?".
- Accent-bordered "takeaway" boxes; rounded cards with a coloured left border; gradient grounds (only a neutral photo scrim or a data ramp may be a gradient); hard dark shadows.
- Data slop: decorative stats, KPI tiles with icons in tinted circles, a chart where one number would do.
- Labels baked into images; screenshots cropped at the top or sides.

### Deck checks before showing
- [ ] Every size is a `--type-*` token; every pad a `--pad` token; nothing under 24px.
- [ ] Titles parallel, read alone they tell the story; no title repeated by its chrome label.
- [ ] Heading y identical across content slides; no content column stopping at 60%.
- [ ] Height budget holds on the fullest slide; no word broken mid-word; no fixed heights clipping text.
- [ ] Full-bleed art reaches all 4 edges; rhythm table passes.
- [ ] Rendered and screenshotted at 1920×1080 and in the scaled stage at 1440, 768 and 390 wide; print preview gives one page per slide, every slide present.

## Prototypes and interactive mockups

### Rules
- Make it feel like the real app: real state, hover/press/focus, validation, transitions, multi-step navigation. A static picture is a mockup, not a prototype.
- No title screen or intro card. Open straight into the product, centred in the viewport or filling it with sensible margins.
- Real elements: `<button>`, `<a href>`, `<input>` + `<label>`. Never `onClick` on a div. Icon-only buttons get `aria-label`; decorative SVG gets `aria-hidden`.
- Targets ≥44px (iOS) / 48dp (Android); text ≥4.5:1 including small grey captions.
- Phone mocks: 390×844, no fake iOS status bar or keyboard. On desktop, centre a 390×844 frame with ~44px radius; honour `env(safe-area-inset-*)`.
- Multi-screen work: one file per screen inside a shared device frame, plus an index gallery.
- Responsive work is a dedicated mobile redesign, not a squeezed desktop. Check 360/390/430/768/1024/1440 for horizontal scroll.
- Domain modules by default: player controls for media, streaks for habits, cart for commerce, balance for finance.
- Prefer a labelled grey placeholder block over a bad attempt (hand-drawn SVG person, fake icon). Real products, places and people get real images, never drawn or generated.
- Content images `object-fit: contain`; `cover` only for croppable decoration.
- Build edit-friendly: flex/grid with `gap`, one stylesheet of custom properties, inline style only for dynamic values, editable text in leaf elements, repeated items written out.
- Files ≤~1000 lines; split by coupling. In-browser Babel scripts don't share scope: share via `Object.assign(window, {...})`, never a global named `styles`.
- Persist current screen or playback position in localStorage (wrapped in try/catch). Label each screen `data-screen-label="03 Checkout"`, 1-indexed.
- Serve over http://localhost, never file://; zero console errors on load.

### Fake data and states
- Demo data per copy.md §5 and the content ranges in process.md §4: one data file with `console.assert` reconciliations, real lengths, realistic distributions, `Intl` formats, labelled synthetic, never invented proof.
- Seed one item selected, one unread and one in an error state so the states show.
- Every prototype reaches all data states (default, loading, every empty kind, error, success) and all 8 control states from the UI or a state switcher. State rules: components.md §4, §11-12.

### Tweaks panel (designer controls)
- Expose 3-5 knobs (accent, type scale, density, dark mode, layout variant) in a small floating panel with its own Show/Hide toggle, wired to CSS custom properties. Sane ranges: scale 0.85-1.3, density 0.6-1.4, colour amount 0-1.
- Keep defaults in one object (`const TWEAK_DEFAULTS = {...}`) so a chosen state can be written back.
- Never ship tweak knobs inside a final product file.

## Presenting variations

- When and how to generate, settle and vary directions (2-4 candidates, nameable axes, identity lock, canon exit, 3+ variations after the pick, donated discipline): process.md §5. Presentation format here.
- Wireframe stage: 3-5 distinct approaches per idea, greyscale with one accent, structure over polish.
- Name every option with a short descriptive label plus a letter (A "Warm editorial"). Never rename or renumber across turns.
- Honest case for EVERY option in chat, not on the artboard: what it is for, its strongest reason, its main trade-off, who it fails. State your pick separately, once, with the reason.
- Format by what varies:
  - Visual-only (colour, type, one static element): side by side on a canvas of labelled artboards at the same size.
  - Flows and interactions: one clickable prototype with an in-page variant toggle, not N separate files.
  - User must pick to proceed: a structured question with the candidates embedded at real size.
- Identical real content across variants so only the axis differs.
- Judge each option on audience identification, product clarity (5 seconds), specificity (a competitor could not use it unchanged), memory (a thing, not a mood, an hour later), restraint and fit to the brief. Never on effort shown.

## Design handoff

- Package: `design_handoff_<feature>/` with `README.md` plus the HTML/CSS/JS references. Screenshots only if the user wants them (ask).
- State up front: the files are design references in HTML, to be recreated in the target codebase's own framework and patterns, not shipped as-is.
- State fidelity: hifi (recreate exactly, final values) or lofi (structure and flow only; style from the codebase's design system).
- README sections, in order:
  1. Overview: what the design is for.
  2. Screens/views: name, purpose, layout (grid, flex direction, widths, heights, padding, gaps), components with position, size, colours (exact hex), type (family, size, weight, line-height, tracking), radius, shadow, border, all states, exact copy.
  3. Interactions and behaviour: navigation, animations (property, duration, easing), loading, error, empty, validation rules, responsive behaviour per breakpoint.
  4. State: variables, transitions and triggers, data fetching.
  5. Tokens: colours, spacing scale, type scale, radii, shadows, motion. Reference tokens by name; systems.md owns the format.
  6. Assets: every image, icon set (with pinned version) and font, with source and licence.
  7. Files: which file holds which screen.
  8. Known gaps: what was not designed (dark mode, an error state, a breakpoint).
- Copy exact values; never round to a 4/8 grid. The README must let a developer who never saw the conversation build it alone.
- Accessibility notes in the handoff: focus order, ARIA roles for custom widgets, contrast pairs, reduced-motion behaviour.

## HTML email

- One self-contained `.html` file. Email clients are not browsers; when a rule here conflicts with web habits, this rule wins.
- Layout: nested `<table role="presentation" cellpadding="0" cellspacing="0" border="0">`; no flex, grid, float or position. One centred wrapper, max-width 600px, single column; stacked rows beat side-by-side columns.
- Inline EVERY style. A `<head><style>` may add only what cannot inline (media queries, dark-mode tweaks); the email must read correctly without it.
- No JavaScript, no external stylesheets, no forms, no video. Web fonts only as progressive enhancement; always an email-safe stack (Arial, Helvetica, Georgia, Verdana, Tahoma) with a generic fallback.
- Type: body 16px (14px floor), line-height in px with `mso-line-height-rule:exactly`, headings 22-32px, ≤2 sizes per block.
- Build the design from coloured cells, spacing, borders and type, not images. Readable with images off; never a single-image email.
- Images: absolute https URLs, `width` attribute plus `style="display:block;max-width:100%;height:auto"`, 2x resolution, meaningful alt text. No hosted image yet: a marked placeholder cell and a note to swap in a URL.
- Bulletproof buttons: a padded `<td>` with `bgcolor` and inline radius, an `<a>` with `display:block` filling it, ≥44px tall, verb + object label. Never an image or `<button>`.
- Outlook (Windows) ignores `max-width`, padding on `<a>`/`<div>` and CSS backgrounds: explicit widths on every table and cell, a 600px ghost table in `<!--[if mso]>…<![endif]-->` around the wrapper, padding on `<td>` only, VML for background images.
- Images are often blocked by default: style the alt text (font, size, colour on the `<img>`) so the layout still reads.
- No hover-dependent content; hover may only restyle a button.
- Dark mode: `<meta name="color-scheme" content="light dark">` and `<meta name="supported-color-schemes" content="light dark">`, `@media (prefers-color-scheme: dark)` plus `[data-ogsc]` overrides; avoid pure #000/#fff grounds; logos as transparent PNG with a light keyline so they survive inversion.
- Mobile: `@media (max-width:600px)` stacks columns and widens buttons to 100%.
- First element in `<body>`: hidden preheader of ~85 characters that extends, never repeats, the subject, padded with `&zwnj;&nbsp;` pairs so body text does not leak into the preview. Subject ≤~50 characters.
- Keep total HTML well under 100KB (Gmail clips at ~102KB).
- `lang` on `<html>`, real `href` links (no dead `#`), a plain-text version for marketing sends, a footer with unsubscribe and a `[POSTAL ADDRESS]` placeholder (never an invented address).
- Show it at 600px and at 390px; test in Gmail, Outlook (Windows) and Apple Mail, light and dark.

## Social and OG images

| Use | Size | Notes |
|---|---|---|
| Open Graph / link preview | 1200×630 (1.91:1) | `og:image` absolute https URL, `og:image:alt`, `twitter:card=summary_large_image` |
| LinkedIn post | 1200×627 | same art as OG |
| Square post | 1080×1080 | |
| Portrait feed post | 1080×1350 (4:5) | most feed area |
| Story / reel / Short cover | 1080×1920 | hard edge y 240-1680 (grid crops); words, faces and characters inside x 60-1020, y 300-1500; best spot y 420-1500 (survives a centre square crop). Full rules: `video.md` |
| Single or album cover | 3000×3000 | streaming stores ask 3000×3000 minimum; still readable at 64px in a playlist row |
| In-game poster or billboard | the game's texture limit | test at the in-world viewing distance (experience.md §7); 3-6 words, flat shapes, no fine print |
| Video thumbnail | 1280×720 | readable at 168px wide in the feed; ≤2MB for YouTube; 0-3 added words. Full rules: `video.md` |

- Keep text and logos in a centred safe area (~1080×540 on OG); platforms crop to 2:1 or near-square.
- Legible at half size: headline ≥64px on a 1200px canvas, ≤~8 words, one supporting line at most, high contrast. Video thumbnails are excluded: they take 0-3 added words (4-5 is a warning, 6+ refused), and no words is a valid default (`video.md`).
- Built from the page's own hero (type, colours, one image), never a bare logo on a gradient and never a stretched screenshot.
- One template per site, rendered per page with that page's headline in the reader's words.
- Multi-format campaigns: compose each ratio on its own (one visual system, same type scale and palette), never one layout squashed across sizes. Carousel = 5-10 frames: a hook frame that earns the swipe, one point per frame, a closing call-to-action frame. Copy in each platform's idiom; no hashtag walls or engagement bait.
- Match the platform feed (light or dark card); PNG for type and flat colour, JPG/WebP for photos, under ~5MB (aim <300KB).
- Never fake proof or UI chrome (fake play buttons, fake notification badges).
- Graphics with words (posters, covers, flyers, cards) are built as HTML or SVG with real fonts and the brand tokens,
  then rendered to PNG in headless Chrome at every size: exact text, editable, versioned. Generated imagery only for
  backgrounds or textures, and only when a blind viewer would not call it AI; real screenshots or footage first.
- A new piece for an existing brand is set beside its last three: if it reads as the same template, change the layout.

## Print and PDF basics

- Decide before the first page: fixed pages (posters, flyers, résumés, certificates, one-pagers, brochure faces: each designed page is one PDF page) or flow (reports, letters, guides: running content that paginates). No size given → Letter for North America, A4 elsewhere; unsure → Letter.
- Units at 96px/in: Letter 816×1056, A4 794×1123, A5 559×794, A3 1123×1587, Tabloid 1056×1632; landscape swaps them. Poster at a given size = inches × 96 (18×24in → 1728×2304). 1pt = 1.333px (12pt = 16px, 9pt = 12px); 1mm ≈ 3.78px. Never vh/vw on paper.
- Margins: ≥40px clear inside every edge for any content, 72px (0.75in) around running text. Backgrounds may bleed to the edge.
- Professional print: add 0.125in (3mm) bleed beyond the trim on every edge, keep text inside the safe area, raster images at 300dpi at final size, expect CMYK shifts (saturated RGB blues and greens dull); ask the printer for their spec.
- Fixed pages: root fixed to the page size, fill the page, budget heights (overflow is clipped, never carried over). Multi-page = a series of pages in reading order; draw running heads and page numbers on each.
- Trifold: 2 landscape faces of 3 panels; outside = inside flap · back · FRONT cover (rightmost); inside = one spread read left to right. Cover promises, inside delivers in three beats, back carries logistics and contact. The tucked flap is ~1/16in narrower, so keep content ≥5% from every fold and edge; dashed fold guides on screen only. Print double-sided, flip on short edge, 100% scale.
- Flow documents: one column of running text; the document opens with its own `<h1>`, then an h2/h3 ladder.
- Browser-printed CSS:
```css
@page { size: A4; margin: 18mm 18mm 20mm }   /* or letter; margin is the printed margin */
html { print-color-adjust: exact; -webkit-print-color-adjust: exact }
h1, h2, h3 { break-after: avoid }  figure, tr, .card { break-inside: avoid }
thead { display: table-header-group }        /* repeat header rows */
p { orphans: 3; widows: 3 }
nav, .controls, video { display: none }
a[href^="http"]::after { content: " (" attr(href) ")"; font-size: .85em }
*, *::before, *::after { animation-delay: -99s !important; animation-duration: .001s !important;
  animation-iteration-count: 1 !important; animation-fill-mode: both !important; transition-duration: 0s !important }
```
- That last rule jumps every animation to its end state. Never `animation: none` in print: it reverts fade-ins to their hidden start. Wait for `document.fonts.ready` before calling `print()`.
- Photos as `<img>`, never `background-image` (dropped or cut by many exporters); caption tall images from above.
- Type: body 12pt (16px) at lh 1.5-1.65, measure 60-75 characters, captions and footnotes ≥9pt (12px), `balance` headings, `pretty` body.
- Tables: header row, rules ≥1px (finer hairlines vanish), numbers right-aligned; every figure and table gets a one-line caption.
- Ink: near-black body on light stock, no large dark floods, grey text no lighter than #767676, strokes ≥1px; must still read in greyscale.
- Flyer: read from across a room in 3 seconds. ONE dominant line ≤6 words at 60pt+ (80px+); the five Ws (what, when, where, cost, how to act: short URL or QR) grouped tight; flat colour and vector shapes over photos and gradients.
- Verify the exported PDF itself, page by page, not the screen render.
